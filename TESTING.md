# Проверки первой версии — 21–22 октября 2026

## Диагностика запуска v0.1.1

После публикации v0.1.0 получен отчёт о молчаливом отсутствии окна на пользовательском
Windows 11 / AMD. Пользователь затем установил причину: Windows блокировала
скачанный файл; запуск разрешается через «Свойства → Разблокировать».
Сбой конвертера на этом компьютере не подтверждён. Изменение упаковки и
диагностика сами по себе не устраняют проверку доверия скачанного файла.

Для v0.1.1 изменена упаковка: self-contained папка вместо самораспаковывающегося
EXE. Добавлены явная точка входа до загрузки WPF, журнал этапов запуска,
сообщение об ошибке загрузки и CMD для трассировки .NET host/кода завершения.
Простой интерфейс использует программную отрисовку и не требует GPU-ускорения.

Расширенный workflow проверяет именно распакованный релизный ZIP, путь с
кириллицей/пробелами, наличие managed/host журналов и нормальное закрытие.
Установленные shared runtimes временно перемещаются с восстановлением в
`finally`, чтобы проверить запуск из приватного runtime пакета. Если изоляция
не удалась, этот этап не считается успешным доказательством автономности.
Актуальный результат доступен в [GitHub Actions](https://github.com/mralex1810/pdf-to-tiff-converter/actions/workflows/windows.yml).

Перечисленные ниже результаты первоначальной версии остаются историей проверок.

## Выполнено

Среда выполнения тестов: macOS Apple Silicon, .NET SDK 10.0.402,
.NET runtime 10.0.13, PDFium 158.0.8111 (macOS arm64), LibTiff.NET 2.4.660.

- **28 из 28 автоматических тестов прошли, exit code 0.** Использован настоящий
  PDFium и декодирование пикселей готовых TIFF, а не подмена конвертера.
- Проверены отдельные файлы и многостраничный TIFF, порядок и поворот страниц,
  изменение размеров при выборе DPI, метаданные разрешения, RGB/оттенки серого/
  1 бит, LZW/Deflate/без сжатия/Group 4, порог чёрно-белого режима.
- Проверено отображение сохранённого поля AcroForm с собственным appearance
  stream — регрессия на исчезающие поля формы.
- Проверены кириллица в путях, повторные конвертации без перезаписи чужих файлов,
  отмена после первой страницы, повреждённый PDF, неверные параметры,
  ограничения входного файла и растрового размера, очистка частичного результата.
- Финальные Windows WPF приложение и UI smoke runner собраны на macOS:
  **0 предупреждений, 0 ошибок**. Это cross-compilation, не запуск Windows GUI.
- Собран self-contained single-file **Windows x64 EXE**. Проверены формат PE,
  встроенные .NET/Windows Desktop runtime 10.0.13, WPF, LibTiff.NET и PDFium.
  Встроенный `pdfium.dll` побайтно совпал с закреплённым Windows x64 NuGet-пакетом;
  macOS/Linux native libraries в EXE отсутствуют.
- Проверены целостность ZIP и наличие лицензий зависимостей. Подробности и
  SHA-256 EXE — в `artifacts/package-verification.json`, SHA-256 ZIP — рядом с ZIP.

## Приложенная пользователем анкета

Двухстраничный PDF конвертирован через CLI с тем же ядром:

- Отдельный файл каждой страницы, 200 DPI, RGB/LZW.
- Один двухстраничный TIFF с теми же параметрами.

Результат независимо прочитан Pillow/libtiff: размер каждой страницы
**1654 × 2339**, DPI **200 × 200**, сжатие **LZW**, режим **RGB**.
Отдельные файлы содержат по одному кадру; многостраничный содержит два.
Пиксели страниц двух режимов совпадают. Обе страницы визуально просмотрены:
текст, таблицы, светло-серые подписи и поля видны.

Два отдельных TIFF занимают 1 021 662 и 836 728 байт. Результаты:
`artifacts/example-tiff.zip`; метаданные: `artifacts/example-verification.json`;
предпросмотр: `artifacts/example-preview.jpg`.

## Windows CI — 22 октября 2026

[Успешный запуск GitHub Actions](https://github.com/mralex1810/pdf-to-tiff-converter/actions/runs/39756956177)
выполнен на Windows x64 (`windows-latest`). Проверены:

- **28 из 28 тестов ядра на Windows**, включая AcroForm, с настоящим Windows PDFium.
- Стандартный запуск приложения и создание настоящего WPF-окна.
- Начальные настройки и переключение Group 4 / цветности.
- Нажатие кнопки конвертации: два отдельных TIFF, прочитанных независимым
  встроенным Windows TIFF-декодером, по одному кадру и 200 DPI.
- Успешное закрытие окна после завершения конвертации; устранён повторный
  вызов `Close()` внутри события `Closing`.
- Самостоятельная сборка через `scripts/publish-windows.ps1`, ZIP и SHA-256.
- Запуск и нормальное закрытие **упакованного self-contained EXE**.

Визуально просмотрен снимок реального Windows-окна из CI. Снимок и TRX-отчёт
доступны в артефакте `windows-results`. Бинарник для GitHub Release собирается
тем же workflow из коммита, на который указывает тег релиза.

GitHub runner не заменяет ручную проверку на чистых Windows 10/11 без .NET
и с отключённой сетью: она пока не выполнена. ARM64 также отдельно не проверялся.
Для такой проверки достаточно распаковать релиз, отключить сеть, сконвертировать
анкету в обоих режимах и проверить отмену/закрытие во время обработки.
